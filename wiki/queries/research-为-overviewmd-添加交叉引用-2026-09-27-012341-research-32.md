# Research: 为 overview.md 添加交叉引用

# 为 overview.md 添加交叉引用

## 背景与目标

`overview.md` 通常是文档仓库或 wiki 的总览页（entry page），其职责是把散落在各个子页面中的条目汇总起来，形成一张可导航的地图。在本 wiki 的语境下，这类总览页需要指向由《数学指南——实用数学手册》整理出的大量条目，例如 [[初等几何公式]]、[[初等代数公式]]、[[初等数学常数]]、[[平面图形面积与周长公式]]、[[空间笛卡儿坐标系]]、[[正多面体]] 与 [[n维球的体积与表面积]] 等，同时也要能够回溯到来源页（如 [[10-数学指南实用数学手册--13-01-初等数学中的基本公式--b2iuhy]]）与实体页（如 [[数学指南-实用数学手册]]）。

因此，"为 `overview.md` 添加交叉引用"这一问题包含两层含义：一是语法层面的链接写法（Markdown 如何表达指向另一文件或某一标题的链接），二是语义层面的引用编号（图表、公式、章节如何被自动编号并引用）。现有资料 [1]–[5] 主要覆盖前者，并在工具链层面部分覆盖后者。

## 交叉引用的三种基本形态

| 形态 | 典型语法 | 是否依赖渲染器/工具链 |
| --- | --- | --- |
| 页内锚点跳转 | `[文本](#anchor)` | 依赖渲染器对标题 id 的生成规则 |
| 跨文件相对链接 | `[文本](./other.md)` | 基本通用，路径解析规则因工具而异 |
| 语义化编号引用 | `[@fig:id]`、`{{< ref "..." >}}` | 强依赖 pandoc-crossref、Hugo 等工具 |

区分这三者是理解后续各方案差异的前提：前两者是纯文本约定，后者则需要构建工具参与。

## 方案一：标准 Markdown 链接与相对路径

内联链接的 Markdown 语法由 `[link text]` 与 `(file-name.md)` 两部分组成，前者是被添加超链接的文本，后者是链接到的 URL 或文件名 [3]。指向仓库内文章（即交叉引用）的链接应使用相对链接，并可使用 `./`（当前目录）、`../`（上一级目录）、`../../`（上二级目录）等相对链接操作数 [3]。

该方案的最大优点是几乎无工具依赖，缺点是无法自动维护编号，一旦目标文件被重命名或移动，链接就会静默失效。

需要注意的是平台差异：有资料明确指出 CSDN 不支持 Markdown 的跳转，在该平台上可以使用 `[toc]` 生成目录作为替代 [1]。这说明"相对链接是否可用"必须结合具体渲染环境验证，而不能假定所有平台行为一致。

## 方案二：引用式链接定义

CommonMark 规范支持两种引用式链接写法：正文中使用 `[label]`、`[label][]` 或 `[text][label]` 引用，然后在文档任意位置用"定义"声明标签对应的目标地址，定义语法形如 `[label]: <url> "optional title"`，其中 `<url>` 与标题均为可选项，标题可以用双引号、单引号或圆括号包裹 [4]。

对于 `overview.md` 这类需要反复指向同一批页面的文档，引用式定义可以把目标路径集中管理在文件末尾，正文只保留语义化的 label，从而降低路径重复带来的维护成本。

## 方案三：Hugo 的 `ref` 与 `relref` 短代码

Hugo 提供 `ref` 和 `relref` 短代码，分别用于显示文档的绝对和相对固定链接 [5]。其参数为内容文档的路径，可以带或不带文件扩展名，也可以带或不带锚点；没有前导 `/` 的路径首先相对于当前页面解析，然后相对于站点的剩余部分解析 [5]。

常见写法包括：

- `{{< ref "document2" >}}`——从 `pages/document1.md` 出发的相对路径
- `{{< ref "document2#anchor" >}}`——带锚点
- `{{< ref "/blog/my-post" >}}`——从任意位置出发的绝对路径
- `{{< relref "#anchor" >}}`——指向同页锚点

Hugo 的路径解析存在两个容易踩坑的特例：`index.md` 可以通过其路径或不含末尾 `/` 的包含文件夹来引用，而 `_index.md` 只能通过其包含的文件夹来引用，直接写 `{{< ref "/about/_index" >}}` 会引发 `REF_NOT_FOUND` 错误 [5]。此外，如果无法唯一解析文档，Hugo 会发出错误或警告，该错误行为是可配置的 [5]。若 `overview.md` 位于 Hugo 站点中并被其渲染，则这一方案能在链接失效时主动报错，安全性优于纯 Markdown 链接。

## 方案四：pandoc 与 `pandoc-crossref`

有资料指出，Markdown 本身并不支持交叉引用，就连 pandoc 本身也不支持，但 pandoc 提供了 `Filter` 过滤器机制，可借助名为 `pandoc-crossref` 的过滤器实现交叉引用 [2]。安装后通过在原有 pandoc 命令上追加一行 `--filter pandoc-crossref` 来调用 [2]：

```text
pandoc --filter pandoc-crossref input.md -o output.docx
```

按该过滤器约定，需要先在对象旁标注 id，再在正文中引用 [2]：

- 图片：标注 `{#fig:id}`，引用 `[@fig:id]`（中间无空格）
- 表格：标注 `{#tbl:id}`，引用 `[@tbl:id]`
- 公式：标注 `{#eq:id}`，引用 `[@eq:id]`
- 章节：标注 `{#sec:id}`，引用 `[@sec:id]`

默认情况下，pandoc 在过滤器帮助下只能形成 `fig.1 … fig.12` 这类连续编号；若需要论文或书籍中常见的、按章节组织的 `fig.2-3` 形式，可在命令中加入参数 `-M chapters` [2]。该方案还支持修改图表默认前缀 [2]。

## 各方案对比

| 方案 | 适用场景 | 编号自动化 | 失效检测 | 主要代价 |
| --- | --- | --- | --- | --- |
| 标准 Markdown 相对链接 [3] | 任意 Markdown 仓库的 `overview.md` | 无 | 无（静默失效） | 需人工维护路径 [1] |
| 引用式链接定义 [4] | 反复指向同一批目标 | 无 | 无 | 定义区需集中维护 |
| Hugo `ref` / `relref` [5] | Hugo 站点内的 `overview.md` | 无 | 有（错误或警告可配置） | 绑定 Hugo 生态 |
| `pandoc-crossref` [2] | 需图表/公式/章节自动编号的长文 | 有 | 有（编译报错） | 需安装过滤器，依赖 pandoc 流程 |

## 已知矛盾与易错点

1. **"交叉引用是否被真正实现"存在歧义。** 有读者反馈，用 `pandoc-crossref` 导出为 Word 后，所谓的引用只是生成的文字，并没有真的在 Word 里构建引用 [2]。这意味着"交叉引用"在导出目标为 Office 格式时，其语义强度弱于原生 Word 的交叉引用域。
2. **重名标题的解析问题。** 有读者询问同一文件下存在两个同名小标题（如 `1.2.1` 与 `2.2.1` 均名为"详细讲解"）时如何引用第二个，作者答复需要给每个小标题添加对应的 id，并通过 id 对应引用 [2]。这与 Hugo 中"无法唯一解析即报错"的行为 [5] 属于同一类问题的不同表现。
3. **渲染器支持程度不一致。** 有资料强调某些 Markdown 写法"看渲染器的支持程度"，换一个编辑器不一定生效 [1]；CSDN 不支持 md 跳转 [1] 即为一例。
4. **表格内复杂内容兼容性差。** 虽然表格不是核心 Markdown 规范的一部分，但 Adobe 在一定程度上支持它们；Markdown 不支持在单元格中使用多个行列表，最佳做法是避免在表格中使用多个行，若单元格需包含多个段落或列表，建议改用标题和文本 [3]。这对 `overview.md` 中"表格化罗列条目 + 逐条说明"的写法构成直接约束。

## 针对 overview.md 的落地建议

- **首选相对链接 + 稳定锚点。** 对 [[海伦公式]]、[[毕达哥拉斯定理]]、[[欧几里得关系]] 这类条目，使用 `[海伦公式](./concepts/海伦公式.md#...)` 形式的相对链接即可满足绝大多数需求 [3]。
- **为标题显式指定 id。** 由于同名小标题会导致引用歧义 [2]，建议在 `overview.md` 的各个小节标题上显式标注 id，避免依赖渲染器自动生成的 slug。
- **集中管理定义。** 若 `overview.md` 中同一目标被引用多次（例如反复指向 [[初等数学常数]] 与 [[阶乘]]），采用引用式链接定义 [4] 可把路径集中在文末，便于批量替换。
- **若站点使用 Hugo，改用 `ref` / `relref`。** 这可获得失效检测能力 [5]，但必须注意 `_index.md` 只能通过文件夹引用的限制 [5]。
- **若需要图表与公式编号，引入 `pandoc-crossref` 并配合 `-M chapters`。** 注意导出到 Word 时编号可能退化为纯文本 [2]。
- **避免在表格单元格内堆叠多段落或列表** [3]，把较长的说明移出表格。

## 内容缺口与建议补充的资料

- 现有资料 [1][4] 对**页内锚点 id 的生成规则**（中文标题、大小写、标点与空格的处理）几乎没有覆盖，而 `overview.md` 中的标题多为中文，这是最需要实证的部分。建议补充 GitHub、GitLab、Hugo、pandoc 各自中文标题 slug 规则的官方文档。
- 缺少**双向链接（bidirectional link）**在标准 Markdown 中的可行方案说明；资料 [4] 的标题虽提及"实现双向的交叉引用"，但摘录内容未展开。
- 缺少**链接失效检测工具**（如 markdown-link-check 等）的资料，而这对于长期维护的 `overview.md` 至关重要。
- 缺少本 wiki 自身渲染环境（`[[wikilink]]` 语法）与标准 Markdown 链接的**共存策略**说明——`overview.md` 若同时使用 `[[concepts/query]]` 与 `[text](path.md)` 两套语法，需明确渲染器的解析优先级。
- 缺少**锚点在跨文件引用时的兼容性**实测数据，尤其是中文锚点在不同平台间的差异 [1][5]。
